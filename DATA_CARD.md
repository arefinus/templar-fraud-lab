# Data card

No real dataset rows are stored in this repository. Three data sources are relevant.

## 1. Synthetic fixture v1 (shipped)

| Field | Value |
|---|---|
| Location | `examples/fixtures/v1/transactions.csv`, `fixture_meta.json`, `FIXTURE.md` |
| Provenance | Authored synthetic demonstration data. Fictional identifiers. Not derived from any person, company, account or dataset. Generated by `tools/make_fixture.py` seed 42, version v1. |
| Record unit | one fictional card transaction |
| Rows | 6,000 (122 labelled fraud; see `fixture_meta.json` for the exact prevalence) |
| Target | `is_fraud` in {0, 1}, drawn from a hand-written logistic model over the features plus Gaussian noise |
| Time | `event_time` (ISO) and `ts` (seconds from origin) over about 180 days, rows sorted chronologically |
| Entity | `card_id` (`SYN-CARD-0001` ...), about 900 cards |
| Numeric | `amount`, `account_age_days`, `velocity_1h`, `ip_risk_score` (10% missing), `country_match` |
| Categorical | `merchant_category` (8 levels, plus `crypto_exchange` appearing only in the final 8% of the timeline), `device_type` (4 levels), `email_domain` (40 levels, 5% missing) |
| Derived by the adapter | `hour`, `dow`, `time_since_last_card_event` (previous event of the same card only) |
| Splits | chronological 70/15/15 by row order; late slice = final 10% of rows |
| Missingness | injected at random into `email_domain` and `ip_risk_score` only |
| Known quirks | the final 8% contains a few amounts multiplied by 40 so that the verifier's range check has something to reject |

## 2. Bank Account Fraud (BAF) Base, not shipped

| Field | Value |
|---|---|
| Provider | Feedzai; Jesus et al., NeurIPS 2022 Datasets and Benchmarks; https://github.com/feedzai/bank-account-fraud (Kaggle mirror available) |
| Terms | CC BY-NC-SA 4.0 (check the repository for the current text) |
| Nature | a SYNTHETIC benchmark of bank ACCOUNT-OPENING applications generated from a real-world source with privacy controls. It is not a table of observed card payments, and results on it should not be described as payment-fraud results. |
| Record unit | one account-opening application |
| Target | `fraud_bool` |
| Time | `month` (0 to 7) only. There is no day-of-week, no card, device or IP identifier, so the paper's day-of-week feature and card-device-IP graph cannot be built from the Base table as published (audit A02). |
| Columns | 30 raw features (25 numeric, 5 categorical) plus `month` and `fraud_bool`; the adapter validates all of them |
| Adapter | `templar_fraud_lab.data.baf.load_baf(data_root)`; expects `Base.csv` |

## 3. IEEE-CIS Fraud Detection, not shipped

| Field | Value |
|---|---|
| Provider | Kaggle competition by IEEE Computational Intelligence Society and Vesta; https://www.kaggle.com/c/ieee-fraud-detection |
| Terms | Kaggle competition rules; download requires a Kaggle account |
| Record unit | one card transaction, identity rows left-joined on `TransactionID` |
| Target | `isFraud` |
| Time | `TransactionDT` (seconds from an unstated origin, about 6 months) |
| Columns | 434 after the merge; the adapter validates `TransactionID`, `TransactionDT`, `isFraud`, `TransactionAmt` and treats listed `M*`, `card4`, `card6`, `ProductCD`, `DeviceType` columns as low-cardinality and the e-mail domain, `addr1`, `DeviceInfo`, `id_30`, `id_31` as high-cardinality |
| Entity key | the community construction `card1|card2|card3|card5|addr1`; the paper does not state its key (audit A11) |
| Adapter | `templar_fraud_lab.data.ieee_cis.load_ieee_cis(data_root)`; expects `train_transaction.csv` and `train_identity.csv` |

## Paper-reported dataset sizes

Transcribed in `evidence/paper_reported/templar.json` under `datasets` with locator "Table 1":
BAF Base 1,000,000 rows and IEEE-CIS 590,540 rows. These figures are paper-reported and were
not verified here because the data was not downloaded.
